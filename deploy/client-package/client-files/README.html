1. About this package

This package installs Comply Solutions into your own Azure subscription. The application, your documents and your data stay in your environment. Comply Solutions does not need access to your Azure account.

FileWhat it is
README.pdfThis guide.
CHANGELOG.txtWhat is new in this version.
install.ps1First-time installation. Run once per environment.
deploy-patch.ps1Installs an update on an existing installation.
settings-template.jsonTemplate for your settings (keys and names). Used by the installer only.
backend.zip, frontend.zipThe application itself. Do not unzip or change these.
lib\common.ps1Shared code used by the two scripts.
version.json, checksums.txtVersion number and file fingerprints. The scripts check them and stop if any file was changed.

What the package includes

  • New analysis: compliance analysis of your internal documents against regulations, with gaps, actions, reviews and the maker, checker and reviewer flow.
  • Documents: Internal Documents, Regulation Documents and the Regulation Points Library. Documents are read with Azure Document Intelligence.
  • Administration: users, departments, settings and AI usage.

The analysis uses the same prompts and settings as the Comply Solutions service on the date of the package. Each update brings the latest ones, unless your administrator has changed them.

Every package you receive has the same layout. A new version is a new package with a new number, for example ComplySolutions-v1.3.0.zip. Keep the previous package folder: you need it to go back a version.

2. How the installation works

Your usersOpen the Comply Solutions web address in a browser and sign in.
Web app (Azure)The screens your users see. Runs in your Azure App Service.
API (Azure)Processing, analysis and security checks. Runs in your Azure App Service.
Supabase (your project)Database, sign-in accounts and document storage, in your own Supabase project.

The installer creates the Azure parts for you, connects them to your Supabase project and starts the application. On first start the application creates all of its database tables by itself. Nothing needs to be created in the database by hand.

Updates replace only the application files. Your settings, users, documents and analysis history are kept.

4. Prepare Supabase and the settings file

4.1 Create the Supabase project

  1. Sign in at https://supabase.com and choose New project.
  2. Choose a region close to your users and a strong database password. Save the password safely; you need it in step 4.2.
  3. When the project is ready, open Database > Extensions, search for vector and enable it.
  4. Open Storage, choose New bucket, name it doc and leave it private (Public bucket switched off).

4.2 Collect the values

Setting in settings.jsonWhere to find it in Supabase
supabase.projectUrlProject Settings > API > Project URL
supabase.anonKeyProject Settings > API Keys > anon public
supabase.serviceRoleKeyProject Settings > API Keys > service_role (secret)
supabase.jwtSecretProject Settings > JWT Keys > Legacy JWT Secret
supabase.databaseConnectionStringClick Connect at the top of the project, choose Session pooler, copy the URI and replace [YOUR-PASSWORD] with your database password

Menu names can differ slightly as Supabase updates its dashboard.

4.3 Create the Azure AI services

Both live in your Azure subscription, so your documents are read and searched inside your own tenant.

  1. Document Intelligence: in the Azure Portal choose Create a resource > Document Intelligence, pick your resource group and region, pricing tier S0. When created, open Keys and Endpoint and copy the endpoint and Key 1.
  2. Azure OpenAI: choose Create a resource > Azure OpenAI, same resource group. When created, open it in Azure AI Foundry, go to Deployments > Deploy model, choose text-embedding-3-small and keep the deployment name text-embedding-3-small. Then copy the endpoint and key from Keys and Endpoint.

4.4 Fill in the settings file

  1. Unzip the package to a folder, for example C:\ComplySolutions\v{{VERSION}}.
  2. Copy settings-template.json to settings.json in the same folder.
  3. Open settings.json in Notepad and replace every value that starts with REQUIRED.
Azure settingMeaning
azure.subscriptionIdYour subscription id (Azure Portal > Subscriptions).
azure.resourceGroupName of the resource group to create or use. Default rg-complysolutions.
azure.locationAzure region, for example uaenorth, westeurope, eastus.
azure.namePrefixShort lowercase name for your organisation (3 to 20 letters or numbers). Your web address becomes https://<prefix>-cs-web.azurewebsites.net.
azure.planSkuServer size. P1v3 is recommended for production; B2 is enough for a test environment.
Keep settings.json private. It contains your keys. Store it like a password, and never email it. The installer copies the values into your Azure App Service settings; updates do not need this file.

5. Install

  1. Open PowerShell (Start menu, type PowerShell).
  2. Go to the package folder: 
    cd C:\ComplySolutions\v{{VERSION}}
  3. Allow the scripts to run for this window only, and unblock the downloaded files: 
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
Get-ChildItem -Recurse | Unblock-File
  4. Run the installer: 
    .\install.ps1
  5. A browser window opens for the Azure sign-in. Sign in with the account that has the Contributor role.
  6. Wait until the script prints Installation complete. The first start takes a few minutes while the application prepares the database.

The script shows each step as it runs: verifying files, signing in, creating resources, saving settings, deploying the API and deploying the web app. If a step fails, it stops and says what to fix. You can safely run install.ps1 again after fixing it.

At the end it prints your web address and the two values used for updates:

Your app:  https://bankalpha-cs-web.azurewebsites.net
Keep these values for future updates:  -ResourceGroup rg-complysolutions  -NamePrefix bankalpha

6. First sign-in and users

6.1 Create the administrator

  1. In Supabase, open Authentication > Users, choose Add user > Create new user, enter your email and a password, and tick Auto confirm user.
  2. Open your web address and sign in with that user once. This creates the user's profile.
  3. In Supabase, open SQL Editor, paste the statement below with your email, and press Run: 
    update profiles
set role = 'super_admin', is_platform_admin = true
where id = (select id from auth.users where email = 'admin@yourbank.com');
  4. Sign out and sign in again. You now have the administrator menus.

6.2 Add your users

As the administrator, open Users in the application to add your colleagues and give each one a role. Users always sign in at your own web address. Their accounts exist only in your Supabase project.

6.3 Your own domain (optional)

To use an address such as compliance.yourbank.com, add a custom domain and certificate to the web App Service in the Azure Portal, then tell Comply Solutions support so the matching settings can be updated.

7. Installing updates

When Comply Solutions releases an update you receive a new package, for example ComplySolutions-v1.3.0.zip, together with its SHA-256 fingerprint in a separate message.

  1. (Recommended) Check the download. In PowerShell: 
    Get-FileHash .\ComplySolutions-v1.3.0.zip -Algorithm SHA256
    The result must match the fingerprint you received. If it does not, do not use the file.
  2. Unzip it to a new folder, for example C:\ComplySolutions\v1.3.0. Keep the old folder.
  3. Read CHANGELOG.txt.
  4. In PowerShell: 
    cd C:\ComplySolutions\v1.3.0
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
Get-ChildItem -Recurse | Unblock-File
.\deploy-patch.ps1 -ResourceGroup rg-complysolutions -NamePrefix bankalpha
  5. Wait for Update complete. The script shows the version before and after.
  6. Open the application, sign in and check that it works.
An update takes about 5 to 10 minutes. Users may see the application restart for about a minute, so plan updates outside busy hours. Your settings, users, documents and history are not changed. If the update includes database changes, the application applies them by itself when it starts.

If you have more than one subscription, add -SubscriptionId <id> to the command.

8. Going back to the previous version

Run deploy-patch.ps1 from the previous package folder with the same values:

cd C:\ComplySolutions\v1.2.0
.\deploy-patch.ps1 -ResourceGroup rg-complysolutions -NamePrefix bankalpha

Database changes made by a newer version only add tables or columns, so the previous version keeps working with them. Contact support before going back more than one version.

10. Troubleshooting

MessageWhat to do
Azure CLI is not installedInstall it (section 3), close PowerShell, open a new window and run the script again.
... cannot be loaded because running scripts is disabledRun the two commands in section 5 step 3 first.
Please fill in '...'A value in settings.json is still empty or still says REQUIRED.
File ... does not match the checksumThe package was changed or damaged. Download it again; do not continue.
Could not create ... The name may already be usedApp names are unique across all of Azure. Choose a different azure.namePrefix and run again.
The API could not prepare the databaseCheck databaseConnectionString (password filled in, Session pooler URI) and that the vector extension is enabled. Fix settings.json and run install.ps1 again.
App Service ... not found (during an update)Use the same -ResourceGroup and -NamePrefix values the installer printed at the end.
Documents stay unread or show a parse errorCheck the Document Intelligence endpoint and key in settings.json, then run install.ps1 again.
Analysis finds no matching passagesCheck the Azure OpenAI endpoint, key and deployment name (text-embedding-3-small), then run install.ps1 again.
Sign-in works but menus are missingComplete section 6.1 step 3, then sign out and in again.

When contacting support, send the full text shown in the PowerShell window (do not include settings.json).

11. Security and support

  • The package contains no keys. Your keys go only into your own Azure App Service settings.
  • The scripts check every package file against checksums.txt before deploying. Never edit the package files.
  • Documents are read and searched by Azure services in your own subscription. AI analysis calls go to the OpenRouter key you provide.
  • Comply Solutions has no access to your Azure subscription or Supabase project unless you grant it.
  • The connection to your application is HTTPS only.
Support: contact your Comply Solutions account manager, quoting your package version ({{VERSION}}) and the text shown by the script.
